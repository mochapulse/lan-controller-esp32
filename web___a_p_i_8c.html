Detailed Description

HTTP endpoint handlers — implementation.

Two handler families: static_handler — serves embedded files (HTML, CSS, JS) from flash. status_handler — builds a cJSON object with chip info, memory, Wi-Fi state, firmware metadata, and sends it as JSON.

Embedded files are linked via objcopy-generated symbols (_binary_<name>_start / _binary_<name>_end) declared here as extern.

Note
esp_clk_cpu_freq() is pulled from esp_private/esp_clk.h because no public equivalent exists in ESP-IDF v6.0.2 for the actual running CPU frequency (as opposed to the configured Kconfig value).

◆ status_handler()

static esp_err_t status_handler ( httpd_req_t *  req)
static

Build and send a /api/status JSON response.

Gathers:

  • Network: Wi-Fi health, LAN IP, MAC address.
  • Memory: heap free/total/min, free stack, task count, uptime.
  • Device: chip model, cores, revision, CPU freq, flash size, features.
  • Firmware: app name, version, build date/time.

All values are read on every request — nothing is cached.

◆ web_API_init()

void web_API_init ( httpd_handle_t  server)

Register all URI handlers.

Register all URI handlers on the given server instance.

Order is significant with wildcard matching:

  1. /api/status — exact JSON endpoint.
  2. /api/wol — exact endpoint to send WoL packet.
  3. / — exact root → index.html.
  4. \/* — wildcard catch-all → static file table.

If '\/*' were registered before /api/status, the wildcard would intercept it because '\/*' matches anything starting with /.
